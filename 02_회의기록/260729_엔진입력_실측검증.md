## 1. AG-07 자료마감일 경계 초과 건수 — 확인 불가

`06_코드/data/input_data/`의 파일 구성은 다음과 같습니다.

**미국 공시 원장이 없습니다.** `accepted_datetime`·`filing_date`·`data_available_date`를 담은 파일이 입력 세트에 존재하지 않습니다. INPUT_MANIFEST 마지막 행이 이를 그대로 기록하고 있습니다.

> `listings.csv` / `halts.csv` / `pit_check.csv` | **도착 대기 (김근형)** | KRX·KIND·DART 공시 | — | 인계 스키마 = 데이터사전 부록 A

따라서 **현재 파일럿 엔진은 `data_available_date`를 소비하지 않습니다.** 이로부터 두 가지가 따라옵니다.

1. **AG-07 결정의 즉시 재산출 영향은 0입니다.** 지수·편입판정 어느 쪽도 지금은 이 필드를 읽지 않습니다.
2. 영향은 **공시 원장이 엔진 입력으로 승격된 시점(AG-16 승격체인)부터** 발생합니다. 즉 AG-07은 "지금 재산출을 유발하는 항목"이 아니라 "승격 전에 확정돼 있어야 하는 항목"입니다.

제가 앞서 재산출 매트릭스에 AG-07을 AG-19와 같은 급으로 넣겠다고 했는데, **입력 구성을 확인한 결과 성격이 다릅니다.** 정정합니다.

## 4. 신규 발견 — 산출물 메타데이터

`output_f1/run_meta.json` 전문입니다.

```json
{
  "rule_version": "v0.9-pilot",
  "valuation_price_source": "RAW_CLOSE_FALLBACK",
  "valuation_note": "adj_close 미확보 — raw_close 평가(D-07 위반 상태), 수정주가 확보 후 재산출 필요",
  "adtv90_observation_end": "data_cutoff_date",
  "index_linking_method": "SEGMENT_RELINK",
  "fx_application": "SAME_DAY_ECOS",
  "calc_days": "COMMON_OPEN_ONLY"
}
```

| # | 발견 | 관련 |
|---|---|---|
| 1 | **`index_linking_method = SEGMENT_RELINK`** — 룰북 B-2·수식부록 §12.2는 같은 방식을 `CHAIN_REBASE_PILOT`으로 부름. 데이터사전 `index_link_method` 허용값도 `CHAIN_REBASE_PILOT / DIVISOR / APPROVAL_PENDING`으로 `SEGMENT_RELINK` 없음 | AG-32·AG-51 |
| 2 | `adtv90_observation_end = data_cutoff_date` — 룰북 제60조는 관측창 종료를 "평가기준일"로 규정. 개정장 A-3은 `data_cutoff_date`. **엔진 구현은 A-3 쪽** | 룰북 내부 모순(E4) |
| 3 | `valuation_note`가 **"D-07 위반 상태"를 스스로 기록** — `RAW_CLOSE_FALLBACK` 사용 사실이 산출물 메타에 명시돼 있음 | AG-31 |
| 4 | 구 `output/thresholds_2026-03-31.json`에는 `data_cutoff_date`·`selection_date`가 없고 P10 값도 다름(KR 73,914,096,486) | F-1 재산출로 갱신됨 |
