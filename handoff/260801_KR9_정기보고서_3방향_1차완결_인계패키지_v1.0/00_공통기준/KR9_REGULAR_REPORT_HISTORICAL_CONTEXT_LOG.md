# KR9 정기보고서 원자료 작업 역사·교정계보

## 문서 역할

이 문서는 실행 로그가 기록하지 못하는 작업 배경, 사용자의 원자료 보관 기억, 용어 교정, 범위 구분과 판단 변경의 역사를 보존한다. 공식 원자료와 해시·실행 로그를 대체하지 않으며, 특별히 표시된 사용자 원자료 역할 확인을 제외하면 REFERENCE_ONLY_NOT_VERIFICATION_BASIS로 사용한다.

## 1. 정기보고서 작업과 기업행사 작업의 분리

> 회사별 PDF·XBRL 원문 패키지 ≠ KR9 기업행사 접수번호·XML 인계패키지

정기보고서 작업은 회사별 폴더와 PDF·재무제표 Excel·원문 XBRL ZIP을 중심으로 구성되었다. 이후 수행한 KR9 기업행사 긴급수집은 종목코드·DART 접수번호·목록 JSON·원문 ZIP·추출 파일을 중심으로 구성되었다. 두 작업은 상호 참조할 수 있지만 동일한 원자료 묶음으로 합산하지 않는다.

## 2. 현대로템 재무제표 원자료 역할 확인

> 현대 로템의 Excel 12 은 재무제표에 해당되는 내용입니다.

따라서 현대로템 raw_files의 Excel 12건은 FINANCIAL_STATEMENT_EXCEL로 분류하며 일반 정제본·분석 워크북과 구분한다.

## 3. XBRL 용어 교정

> 그..xml 이 아니라 xbrl 이에요

기술 구현에서 XBRL 인스턴스와 링크베이스가 XML 문법으로 읽히더라도, 프로젝트 문서에서는 원문 XBRL ZIP, XBRL 인스턴스, XBRL 링크베이스 구성파일이라는 용어를 우선 사용한다.

## 4. XBRL 구조검사 변경계보

B2의 파일명 기반 검사에서는 98건이 즉시 완전구조로 확인되고 93건이 임시 REVIEW 상태가 되었다. B3에서 XBRL 인스턴스와 링크베이스 내용을 직접 검사한 결과 93건 모두 XBRL_FULL_STRUCTURE_CONTENT_CONFIRMED로 재분류되었다. 따라서 임시 REVIEW는 원문 이상이 아니라 검사방식의 한계였다.

## 5. PDF-XBRL 대응표 탐색 변경계보

B4A에서는 회사별 기준 ZIP 내부에서 정확한 pdf_xbrl_pairing.csv를 찾지 못했으나 9개 회사 모두에서 대체 대응·QA 후보가 확인되었다. 이 결과는 대응근거 부재가 아니라 탐색 위치 가정 불일치로 해석하며, B4B에서 outputs 전체의 압축해제 폴더와 최상위 ZIP을 다시 탐색한다.

## 6. 현대로템 파일럿에서 KR8 확장

> 처음엔 한번에 9개를 실험대에 놓을 수 없으니 하나를 먼저 실험을 완료하고 나서 샘플로 삼아 나머지 8개 ZIP을 실행하였다.

한국 정기보고서 원자료 공정은 현대로템 1개사를 파일럿으로 먼저 수행하였다. 현대로템에서 PDF·재무제표 Excel·원문 XBRL의 수집, 정제 워크북 작성, 구조검사와 QA 방식을 반복 실험한 뒤 이를 기준 샘플로 삼아 나머지 8개 회사에 확장하였다.

따라서 현대로템에는 여러 정제 버전과 QA 자료가 남아 있고, KR8에는 표준화된 INPUT_PACKAGE와 별도의 검토 산출물이 존재한다. 이 차이는 누락이나 오류가 아니라 파일럿 1개사에서 배치 8개사로 확장된 개발계보를 반영한다.

## 8. 현대로템 v1.1 한국어 접미사 변수보간 교정

5D-B4D-2A는 폴더본과 ZIP본 원자료 56건의 SHA-256이 모두 일치하여 TECHNICAL_PASS로 종료되었다.

5D-B4D-2B는 기준원장 계산 이후 누적 로그를 작성하는 과정에서 $PairCount건, $PdfOnlyCount건, $XbrlOnlyCount건이 각각 하나의 변수명으로 해석되어 중단되었다.

이를 ${PairCount}건, ${PdfOnlyCount}건, ${XbrlOnlyCount}건으로 교정하였다. 이 교정은 원자료·기준원장·판정규칙을 변경하지 않으며 출력 문자열의 변수경계만 명시한다.

실패한 실행결과는 스크립트 오류계보로 보존하고, 교정 후 재실행 결과를 5D-B4D-2B의 유효한 기술판정으로 사용한다.
