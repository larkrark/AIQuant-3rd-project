# KR9 정기보고서 원자료 검증 누적 로그

## 기록 원칙

각 단계의 원본 RUN_SUMMARY와 CSV는 변경하지 않고 보존한다. 이 문서는 원본 로그를 사람이 이해할 수 있도록 연결한 작업용 누적 기록이다. 기술적 파일검사와 독립 QA, 팀 승인, 엔진 입력, 운영 승격을 서로 구분한다.

## 5D-B1 회사별 기준 패키지 식별

회사별 기준 정기보고서 패키지 9개를 검사한 결과 9개 패키지가 모두 발견되었고 외부 ZIP 개방에 성공하였다. 기준 패키지의 raw_files에서는 보고서 PDF 204 건, 재무제표 Excel 12 건, 원문 XBRL ZIP 191 건을 확인하였다. 재무제표 Excel 12 건은 모두 현대로템 공식 재무제표 원자료이며 일반 분석 산출물과 구분한다.

기술적 판정은 PASS이다. 이 단계는 파일 존재와 형식별 수량을 확인한 것이며, PDF와 XBRL 내용의 보고서별 대응이 최종 확인되었다는 의미는 아니다.

## 5D-B2 원문 XBRL ZIP 구조·무결성 검사

원문 XBRL ZIP 191 건을 외부 회사 패키지 안에서 직접 열어 검사하였다. 모든 원문 XBRL ZIP이 정상적으로 열렸고, 내부 XBRL 구성파일 1430 건 중 1430 건이 읽기와 SHA-256 계산을 통과하였다. 빈 XBRL ZIP과 내부 읽기 오류는 발견되지 않았다.

파일명 기반 구조검사에서는 98 건이 즉시 완전구조로 분류되었고 93 건은 XBRL 인스턴스와 XSD 스키마가 확인되었으나 링크베이스 역할을 파일명만으로 완전히 구분하지 못해 검토 상태로 남았다.

## 5D-B3 XBRL 내용 기반 구조 재검사

B2의 구조검토 대상 93 건에 대해 XBRL 인스턴스와 링크베이스 내용을 직접 검사하였다. 구현 출력의 XmlFilesRead=558 는 일반 XML 원문 수가 아니라, 검토 대상 XBRL ZIP 안에서 읽은 XBRL 인스턴스·링크베이스 구성파일 수이다.

재검사 결과 93 건 모두 XBRL_FULL_STRUCTURE_CONTENT_CONFIRMED 상태로 재분류되었다. 인스턴스와 스키마가 확인된 ZIP은 93 건이며, 계속 검토가 필요한 ZIP은 0 건이다. 따라서 원문 XBRL ZIP 191 건의 구조·개방·내부 읽기 검사는 기술적으로 PASS이다.

## 5D-B4A 기존 PDF-XBRL 대응표 탐색

회사 패키지 안의 기존 PDF-XBRL 대응표와 관련 QA 자료를 탐색하였다. 정확한 pdf_xbrl_pairing.csv는 0 개 파일, 0 개 회사에서 발견되었다. 기존 대응표 전체 행은 0 행이며 CSV 파싱 오류는 0 건이다.

기존 상태값 기준으로 PDF_XBRL_PAIR 0 건, PDF_ONLY 0 건, REVIEW_PAIR_CONTENT 0 건을 확인하였다. 정확한 대응표가 없는 회사는 새 규칙으로 임의 대응시키지 않고, 발견된 대체 QA·워크북 후보를 후속 검사 대상으로 유지한다.

## 5D-B4C KR8 대응표 중복제거와 상태어휘

B4B에서 발견한 대응표 사본 17개를 SHA-256 기준으로 중복 제거한 결과 KR8 회사별 고유 대응표 8개가 확인되었다. 고유 대응표 8개는 모두 해시 재검산과 CSV 파싱을 통과하였다.

복사본을 포함한 상태기록은 188건이었으나 파일 해시·행번호·열·상태값 기준으로 중복을 제거한 결과 고유 상태기록은 94건이었다. LG CNS는 PDF_XBRL_PAIR 11건과 PDF_ONLY 13건, LIG넥스원은 PDF_XBRL_PAIR 22건, 효성중공업은 PDF_ONLY 24건, 현대오토에버는 PDF_XBRL_PAIR 24건으로 확인되었다.

LS일렉트릭 22행, 한화에어로스페이스 19행, 삼성SDS 23행, HD현대일렉트릭 24행은 고유 대응표가 존재하지만 현재 표준 상태어휘와 다른 열 또는 값을 사용하였다. 따라서 대응근거 부재가 아니라 상태어휘 해석 미완료로 분류하고 B4C-2에서 원본 열과 값을 확인한다.

## 5D-B4C-2 PAIRED 원본 상태어휘 확인

LS일렉트릭 22행, 한화에어로스페이스 19행, 삼성SDS 23행, HD현대일렉트릭 24행의 고유 대응표를 확인한 결과 총 88행 모두 원본 pair_status 값으로 PAIRED를 사용하였다.

report_type과 report_type_kr의 사업보고서·반기보고서·분기보고서는 대응상태가 아니라 보고서 종류이다. 따라서 이전 미등록 상태어휘 집계에는 상태열 외 보고서 종류열이 함께 포함되어 있었다.

PAIRED는 PDF_XBRL_PAIR의 표준화 후보로 두며, B4C-3에서 각 행의 PDF·XBRL 파일 참조와 실제 원자료 존재를 대조한 뒤 최종 승격 여부를 판단한다.

## 5D-B4C-3 PAIRED 파일참조 검증

LS일렉트릭·한화에어로스페이스·삼성SDS·HD현대일렉트릭의 원본 PAIRED 88행을 검사하였다. 88행 모두 PDF 참조와 XBRL 참조를 포함했고, 각 참조파일은 회사별 기준 원자료 패키지에서 실제로 확인되었다.

따라서 원본 상태값 PAIRED 88건은 보존하되 기술적 표준상태 후보 PDF_XBRL_PAIR 88건으로 대응시킬 수 있다. 이 판정은 파일 대응관계의 기술검증이며 독립 QA 또는 팀 승인값을 뜻하지 않는다.

## 5D-B4C-4 KR8 대응상태·원자료 수량 정산

KR8의 보고서 PDF 182 건과 원문 XBRL ZIP 169 건을 고유 대응표 상태와 정산하였다. 표준 PDF_XBRL_PAIR는 145 건, PDF_ONLY는 37 건, REVIEW_PAIR_CONTENT는 0 건이며 PDF 상태 커버리지는 182 건이다.

PDF 상태 커버리지는 전체 PDF 수와 일치하는지 검사하였다. 대응된 PDF 외에 남는 XBRL ZIP은 24 건이며, 이 값이 0보다 큰 회사는 원문 손상으로 단정하지 않고 대응표 작성시점·공정범위·후속 보충수집 여부를 검토하는 공개 항목으로 유지한다.

현재 기술 정산 상태는 PASS_WITH_ATTENTION 이다.

## 5D-B4C-5A 효성중공업 대응표·원자료 구조 확인

효성중공업은 보고서 PDF 24건과 원문 XBRL ZIP 24건을 보유하지만 기존 고유 대응표 24행의 상태는 모두 PDF_ONLY로 기록되어 있다. 이번 단계에서는 기존 PDF_ONLY 상태를 변경하지 않고 대응표의 실제 열·참조값과 현재 원자료 파일명을 확인하였다.

대응표 행은 24 행, PDF_ONLY는 24 행이다. PDF 참조가 있는 행은 24 행이며 실제 PDF 원자료와 일치한 행은 0 행이다. XBRL 참조가 있는 행은 24 행이고, 현재 raw_files에는 별도로 XBRL ZIP 24 건이 보관되어 있다.

현재 관찰상태는 PAIRING_AND_SOURCE_SCOPE_DIFFERENCE_REVIEW 이다. 이는 대응표 작성시점과 현재 원자료 보관상태의 차이를 나타내며, XBRL이 언제·어떤 공정에서 추가되었는지는 아직 확정하지 않는다.

## 5D-B4C-5C 효성중공업 PDF_ONLY 원자료 계보

정기보고서 원자료는 모든 보고기간에 PDF·XBRL·재무제표 XLSX가 함께 제공된 구조가 아니었다. 원문 제공상태에 따라 PDF만 존재하는 보고서가 많았으며, XBRL 또는 XLSX가 없는 경우도 정상적인 원자료 제공상태로 기록한다.

효성중공업 고유 대응표 24행은 모두 PDF_ONLY이며 PDF 파일명 24건은 실제 원자료와 일치한다. 행별 XBRL 파일명은 기록되어 있지 않다. 현재 별도 보관 중인 XBRL ZIP 24건은 존재하지만 이를 과거 PDF_ONLY 행에 자동 소급 대응시키지 않는다.

따라서 원수집 이용가능상태는 PDF_ONLY, 현재 보관상태는 XBRL_PRESENT, 직접 대응기록은 NOT_RECORDED, 소급대응은 NOT_PERFORMED로 분리한다.

## 5D-B4D-2A·2B 현대로템 원자료 미러·기준원장 정산
