# 부록: 정규화·조립·검증·봉인의 의미

## 1. 이 부록의 목적

이 부록은 정기보고서 원자료 작업에서 사용한 기술용어를 초보자도 같은 의미로 이해할 수 있도록 정리한다.  
각 용어는 다음 일곱 항목으로 설명한다.

1. 목적
2. 입력
3. 처리방식
4. 산출물
5. 정상 완료 기준
6. 원자료 변경 여부
7. 승인 경계

---

## 2. 1차 완결 산출물

### 쉬운 뜻

제작자가 맡은 범위의 수집·정리·추적·기술검증·인계 준비를 모두 끝낸 산출물이다.  
독립 QA와 팀 승인은 이 산출물을 완성시키는 작업이 아니라, 완성된 산출물을 다른 사람이 검증하고 승인하는 후속 절차이다.

### 목적

제작자 담당범위의 완료상태와 후속 검증·승인상태를 분리한다.

### 입력

- 원자료
- 정제·대응원장
- 단계별 검증결과
- 오류 교정이력
- 인수인계 문서

### 처리방식

필수 산출물과 증거를 모두 연결하고, 후속 수신자가 즉시 검토를 시작할 수 있도록 구성한다.

### 산출물

- 공통 기준원장
- 3방향 인계본
- 근거증거원장
- 무결성 기록
- 최종 ZIP

### 정상 완료 기준

- 제작자 담당범위 누락 0건
- 필수파일 누락 0건
- 원자료 혼입 0건
- ZIP CRC 오류 0건

### 원자료 변경 여부

원자료를 수정하지 않는다.

### 승인 경계

`1차 완결`은 독립 QA 완료나 팀 승인을 뜻하지 않는다.

---

## 3. 정규화

### 쉬운 뜻

서로 다른 이름·날짜·상태·파일형식을 비교할 수 있도록 공통 규칙에 맞추는 작업이다.

예를 들어 다음 두 이름이 같은 단계를 가리킨다고 판단할 수 있도록 구분기호와 대소문자를 일정하게 처리한다.

```text
stage5d_b4c5c-and-b4d1
stage5d_b4c5c_and_b4d1
```

### 목적

표현 차이 때문에 같은 자료가 서로 다른 자료처럼 보이는 문제를 줄인다.

### 입력

- 파일명
- 회사명
- 종목코드
- 보고기간
- 상태값
- 날짜값

### 처리방식

- 하이픈·밑줄 등 구분기호 정리
- 대소문자 통일
- 회사명과 종목코드 연결
- 날짜 형식 통일
- 상태어휘를 정해진 값으로 매핑

### 산출물

- 표준 회사명
- 표준 종목코드
- 표준 날짜
- 표준 상태코드
- 비교 가능한 파일키

### 정상 완료 기준

같은 대상을 같은 키로 인식하고, 다른 대상을 잘못 합치지 않아야 한다.

### 원자료 변경 여부

원자료 파일은 변경하지 않는다. 비교용 값이나 별도 원장만 만든다.

### 승인 경계

정규화는 표현을 통일할 뿐, 경제적 의미나 승인값을 자동 확정하지 않는다.

---

## 4. 조립

### 쉬운 뜻

이미 완료된 검증결과를 새로 분석하는 것이 아니라, 공통 기준원장 하나를 중심으로 수신자별로 읽기 쉽게 배열하는 작업이다.

### 목적

독립 QA·엔진·선정방법론 담당자가 같은 기준을 서로 다른 방식으로 해석하는 문제를 방지한다.

### 입력

- 누적로그
- 회사별 상태표
- 단계별 검증결과
- 근거파일
- 승인경계

### 처리방식

1. 공통 기준원장을 만든다.
2. 각 근거파일을 기준원장과 연결한다.
3. 수신자별 필요한 열과 안내문을 만든다.
4. 공통원장과 수신자별 보기의 수량을 맞춘다.

### 산출물

- `00_공통기준`
- `01_김민호_독립QA`
- `02_권보성_엔진인계`
- `03_추주원_선정방법론`

### 정상 완료 기준

- 공통원장과 수신자별 보기 사이 수량 불일치 0건
- 필수 설명 누락 0건
- 승인경계 혼동 0건

### 원자료 변경 여부

원자료를 변경하지 않는다. 검증요약과 인계문서를 복사·배열한다.

### 승인 경계

조립 완료는 독립 QA나 팀 승인 완료를 뜻하지 않는다.

---

## 5. 미러검사

### 쉬운 뜻

폴더에 있는 파일과 ZIP에 들어 있는 파일이 실제로 같은지 확인하는 검사이다.

### 목적

전달용 ZIP을 만들면서 파일이 빠지거나 다른 버전이 들어가는 문제를 찾는다.

### 입력

- 폴더본 파일
- ZIP 내부 파일
- 파일별 SHA-256

### 처리방식

파일명·크기·SHA-256을 각각 비교한다.

### 산출물

- 일치 목록
- 누락 목록
- 예상하지 않은 파일 목록
- 해시 불일치 목록

### 정상 완료 기준

필수 대상의 파일명·수량·SHA-256이 모두 일치해야 한다.

### 원자료 변경 여부

읽기 전용 검사이므로 원자료를 변경하지 않는다.

### 승인 경계

미러 일치는 파일이 같다는 뜻이며, 파일 내용의 회계적 의미까지 검증했다는 뜻은 아니다.

---

## 6. 기준원장

### 쉬운 뜻

어떤 회사·파일·상태를 공식 비교기준으로 사용할지 정한 중심 목록이다.

### 목적

여러 복사본이나 중간표 중에서 어느 표를 기준으로 검사했는지 명확히 한다.

### 입력

- 회사 목록
- 파일 목록
- 종목코드
- 보고기간
- 상태값
- 보관경로

### 처리방식

중복본을 구분하고, 기준으로 사용할 한 개의 원장과 버전을 지정한다.

### 산출물

- 회사별 기준파일
- 기준 행 수
- 기준 상태
- 기준 버전과 해시

### 정상 완료 기준

모든 검사결과가 같은 기준원장을 참조해야 한다.

### 원자료 변경 여부

기준을 지정할 뿐 원자료를 변경하지 않는다.

### 승인 경계

기준원장은 기술검증의 기준이며 팀 승인값 원장과 동일하지 않을 수 있다.

---

## 7. 대응원장

### 쉬운 뜻

서로 관련된 자료를 한 행에서 연결한 표이다.  
이 프로젝트에서는 PDF와 XBRL ZIP의 관계가 대표적인 사례이다.

### 목적

어떤 PDF에 어떤 XBRL이 직접 대응하는지, 또는 한쪽 자료만 있었는지 추적한다.

### 입력

- PDF 파일명
- XBRL ZIP 파일명
- 회사
- 보고기간
- 수집 당시 상태

### 처리방식

각 자료를 보고기간과 직접 기록을 기준으로 연결하고 다음 상태를 구분한다.

- 직접대응
- `PDF_ONLY`
- `XBRL_ONLY`

### 산출물

회사별 PDF-XBRL 대응원장

### 정상 완료 기준

- 직접대응 파일참조 누락 0건
- `PDF_ONLY`와 `XBRL_ONLY`의 근거 존재
- 현재 보관상태와 과거 수집상태 분리

### 원자료 변경 여부

원자료는 변경하지 않는다.

### 승인 경계

현재 XBRL이 존재한다고 해서 과거 PDF에 자동으로 소급 대응하지 않는다.

---

## 8. 무결성검사

### 쉬운 뜻

파일이 빠지거나 비어 있거나 바뀌지 않았는지 확인하는 검사이다.

### 목적

인계 과정에서 발생할 수 있는 누락·변조·중복·혼입을 찾는다.

### 입력

- 최종 패키지 파일
- 필수파일 목록
- 파일 크기
- SHA-256
- ZIP 엔트리

### 처리방식

- 필수파일 존재 확인
- 빈 파일 확인
- 금지된 원자료 혼입 확인
- 파일별 SHA-256 계산
- ZIP 전체 엔트리 개방

### 산출물

- `FILE_MANIFEST.csv`
- `SHA256SUMS.csv`
- `PACKAGE_QA_CHECKLIST.csv`
- `PACKAGE_QA_SUMMARY.txt`

### 정상 완료 기준

- 필수파일 누락 0건
- 빈 파일 0건
- 원자료 혼입 0건
- ZIP CRC 오류 0건

### 원자료 변경 여부

검사대상을 읽기만 한다.

### 승인 경계

무결성 PASS는 전달파일이 온전하다는 뜻이며, 독립 재산출 결과가 같다는 뜻은 아니다.

---

## 9. 봉인

### 쉬운 뜻

최종 패키지의 파일목록과 해시를 만들고 ZIP으로 고정하여, 이후 같은 버전인지 확인할 수 있게 하는 작업이다.

### 목적

인계 이후 파일이 추가·삭제·변경되었는지 확인할 수 있도록 제출상태를 고정한다.

### 입력

- 무결성검사를 통과한 패키지 폴더
- manifest
- SHA-256 목록
- 패키지 QA 결과

### 처리방식

1. 최종 파일목록을 만든다.
2. 파일별 SHA-256을 계산한다.
3. 패키지 QA 요약을 작성한다.
4. ZIP을 생성한다.
5. ZIP 전체 엔트리를 다시 읽어 CRC를 검사한다.

### 산출물

최종 인계 ZIP과 무결성 기록

### 정상 완료 기준

최종 ZIP에 필수 무결성 기록이 모두 포함되고 CRC 오류가 없어야 한다.

### 원자료 변경 여부

원자료는 변경하지 않는다.

### 승인 경계

봉인은 해당 버전을 고정하는 절차이며, 팀 승인 자체가 아니다.

---

## 10. 재귀검색

### 쉬운 뜻

지정한 폴더의 바로 아래만 보는 것이 아니라, 그 안의 하위폴더까지 계속 내려가며 파일을 찾는 방식이다.

### 목적

결합 실행결과처럼 요약파일이 하위폴더에 보관된 경우 증거를 놓치지 않는다.

### 입력

- 단계 진단폴더
- 요약파일 이름규칙

### 처리방식

다음 우선순위로 검색한다.

1. 최상위 `RUN_SUMMARY.txt`
2. 하위 `COMBINED_RUN_SUMMARY.txt`
3. 하위 `RUN_SUMMARY.txt`
4. 기타 `*SUMMARY*.txt`·`*요약*.txt`

### 산출물

- 선택된 요약경로
- 요약판정방식
- 요약후보수

### 정상 완료 기준

증거가 실제로 존재할 때 폴더구조 차이 때문에 누락으로 오판하지 않아야 한다.

### 원자료 변경 여부

읽기 전용 검색이므로 변경하지 않는다.

### 승인 경계

재귀검색은 증거의 위치를 찾는 절차이며, 검색된 모든 파일을 동일한 효력의 근거로 자동 인정하지 않는다.

---

## 11. 독립 QA

### 쉬운 뜻

제작자가 만든 결과를 그대로 믿고 확인하는 것이 아니라, 다른 사람이 같은 원자료와 규칙으로 다시 계산해 차이를 찾는 절차이다.

### 목적

제작자의 코드·가정·수기 판단에서 발생할 수 있는 오류를 독립적으로 확인한다.

### 입력

- 1차 완결 산출물
- 원자료 접근경로
- 룰북
- 데이터사전
- 결정로그

### 처리방식

- 대표 표본 재산출
- 수량·해시 재검사
- 상태값 차이 비교
- 제작자 결과와 독립 결과의 차이 기록

### 산출물

- 독립 QA 결과표
- 차이표
- 재검토 요청
- QA 판정

### 정상 완료 기준

검사범위와 결과, 차이, 미결사항이 모두 기록되어야 한다.

### 원자료 변경 여부

원자료를 변경하지 않는다.

### 승인 경계

독립 QA PASS도 팀 승인과 동일하지 않다.

---

## 12. 승인경계

### 쉬운 뜻

누가 어디까지 완료했고, 어떤 값이 아직 승인 전인지 구분하는 선이다.

### 목적

기술적으로 확인된 사실을 팀 승인값이나 엔진 입력값으로 잘못 해석하지 않도록 한다.

### 핵심 구분

```text
검토후보값
≠ 팀승인값
≠ 엔진입력값
```

### 현재 패키지의 경계

```text
제작자 담당범위   완료
산출물 상태       1차 완결
독립 QA           후속 단계
팀 승인           후속 단계
엔진 승격         승인 전 차단
```

---

## 13. 전체 흐름

```text
원자료 수집
→ 정규화
→ 기준원장·대응원장 작성
→ 기술검증
→ 미러검사
→ 3방향 조립
→ 무결성검사
→ 봉인
→ 독립 QA
→ 팀 승인
→ 엔진 승격
```
