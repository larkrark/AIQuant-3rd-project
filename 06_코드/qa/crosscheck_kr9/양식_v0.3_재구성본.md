## 1. 문서 목적

동일한 프로젝트 산출물을 서로 독립적으로 검토한 뒤, 두 결과가 어디까지 일치하고
어느 단계에서 처음 달라졌는지를 공통된 방식으로 확인하기 위해 작성한다.

교차검토는 어느 한쪽의 결과를 먼저 정답으로 정하는 작업이 아니다. 동일한 원자료에
규칙을 적용했는지 확인하고, 결과가 다른 경우 그 원인이 원자료·자료 이용시점·모집단·
연산·상태판정·코드 또는 문서 적합성 가운데 어디에서 발생했는지를 함께 찾는 과정이다.

① 기준 산출물과 독립 검토 산출물의 일치 여부 확인
② 차이 또는 특이사항이 처음 발생한 단계 확인
③ 확인된 사실과 추정 원인의 구분
④ 후속 단계에 미치는 영향범위 파악
⑤ 문서 수정 또는 재산출 필요 여부 결정
⑥ 최종 승인과 성과 대결 전 미결사항 확인

## 2. 적용 대상

원자료의 식별자, PIT·날짜, 테마 적격성, 시즈닝·시장상태, 거래대금·ADTV90,
P10·재무조건, 구성종목·가중, 커스텀 지수, 벤치마크·환율, 성과지표 및
문서·결정로그 적합성을 교차검토할 때 사용한다.

## 3. 교차검토 기본원칙

**3.1 결과보다 비교조건을 먼저 확인한다.**
두 결과를 비교하기 전, 같은 원자료·기준일·룰버전과 결정조건을 사용했는지 먼저 확인한다.
비교조건이 다르면 결과가 다른 것을 오류로 단정하지 않고 `비교조건 불일치`로 기록한 뒤
조건을 맞추어 다시 검토한다.

**3.2 원자료부터 최종 결과까지 순서대로 비교한다.**
원자료 → 식별자 연결 → PIT·날짜 → 테마 및 게이트 판정 → 시즈닝·시장상태 →
거래대금·ADTV90 → P10·재무조건 → 구성종목 → 종목 가중 → 지수·BM·성과 순으로 비교한다.

**3.3 최초 차이단계를 중심으로 기록한다.**
전 단계의 차이로 이후 결과가 연쇄적으로 달라진 경우, 다음 차이를 모두 별개의 오류로
기록하지 않는다. 최초로 달라진 단계와 그 이후 파생영향을 구분하여 적는다.

**3.4 사실과 추정을 구분한다.**
확인된 사실, 추정 원인, 확인된 원인, 특이사항을 구분하여 작성하고,
추정 원인을 확인된 사실처럼 기록하지 않는다.

**3.5 교차검토용 표시를 공식 승인값으로 사용하지 않는다.**
본 양식의 `일치`, `특이사항`, `재검토 필요` 등의 표시는 교차검토 업무를 위한 기록이다.
데이터사전의 공식 허용값이나 산출 자격 상태로 자동 승격하지 않는다.

## 4. 작성 및 검토 절차

① 비교할 기준 산출물과 독립 검토 산출물을 지정한다.
② 원자료·기준일·룰버전·결정 ID 등 비교조건을 확인한다.
③ 원자료부터 최종 결과까지 단계별로 비교한다.
④ 서로 다른 결과가 처음 나타난 단계를 확인한다.
⑤ 차이와 특이사항을 근거자료와 함께 기록한다.
⑥ 이후 단계에 미칠 영향을 구분한다.
⑦ 문서 수정 또는 재산출 범위를 판단한다.
⑧ 수정 후 같은 양식으로 다시 검토한다.
⑨ 미해결 불일치가 없을 때 승인 검토단계로 넘긴다.

## 5. 검토결과의 활용

결과가 일치하면 독립 재산출 근거로 보존한다. 반올림 등 미세한 차이만 있으면 허용오차와
반올림 기준을 기록한다. 원인이 확인된 차이는 문서 또는 코드 수정 여부를 결정하고,
비교조건이 다르면 조건을 통일한 뒤 재검토한다. 원인이 확인되지 않은 불일치는
승인과 성과 대결을 보류한다.

## 6. 자료 제출 및 보존

작성 자료는 수기 교차검토표와 함께 기준 산출물, 독립 검토 산출물, 원자료 목록과 버전,
적용 문서버전과 결정 ID, 차이·특이사항 근거, 수정 전후 산출물, 재산출 결과 및
최종 승인·보류 사유를 보존한다.

# 부속 5. 문서 사용 안내

**1. 사용 목적** — 두 결과가 어디까지 일치하고 어느 단계에서 처음 달라졌는지 확인한다.

**2. 사용 시점** — 독립 재산출 결과와 기준 산출물을 비교할 때, 수집 결과와 수기검산 결과를
비교할 때, ADTV90·P10·구성종목·가중·지수값 등이 서로 다를 때, 또는 오류는 아니지만 별도
설명이 필요한 특이사항이 있을 때 사용한다. 한 문서에는 가급적 하나의 검토대상 또는
하나의 회차를 기록한다.

**3. 작성 역할** — 기준 산출 역할은 기존 수집이나 담당 산출을 통해 결과를 만든 쪽이다.
독립 검토 역할은 기준 산출의 계산과정을 그대로 복사하지 않고 원자료·룰북·데이터사전·
산식부록을 기준으로 다시 확인하는 쪽이다.

**4. 전체 사용 흐름** — 검토대상 지정 → 비교조건 확인 → 원자료부터 순서대로 결과 비교 →
최초 차이단계 확인 → 차이·특이사항 상세기록 → 영향범위 판정 → 수정·재산출 →
같은 양식으로 재검토 → 종합판정

**5. 비교조건 사전확인** — 결과값을 비교하기 전에 원자료 파일과 해석, 기준일과 자료마감일,
유니버스와 모집단, 룰북·산식·결정 버전, PIT 규칙, 분모와 계산방식, 가격의 PR·TR 기준,
환율·시장달력, 통화·단위와 반올림 기준이 같은지 확인한다.

**6. 결과 비교 순서** — 원자료 → 식별자 연결 → PIT·날짜 → 테마 적격성 → 시즈닝 →
시장상태 → 거래대금 → ADTV90 → P10·재무조건 → 구성종목 → 가중 → 지수 → BM·환율 →
성과 → 문서·결정로그 순서로 확인한다.

> **검토범위에 포함되지 않은 항목은 `해당 없음`, `검토범위 밖` 또는 `NA`로 기록한다.**
> **확인하지 않은 항목을 `일치`로 표시하지 않는다.**

**7. 결과가 다를 때의 기록방법** — 가장 중요한 것은 최종 결과가 아니라 처음 달라진 단계다.
추정 원인과 확인된 원인을 분리하고, 근거를 확인하기 전에는 코드 오류라고 단정하지 않는다.

**8. 수치와 판정 결과 비교** — 절대차이·상대차이율·허용오차와 판정을 기록한다.
허용오차는 검토자가 임의로 정하지 않고 산식부록·테스트 기준·팀 승인값이 있을 때만 사용한다.

**9. 상세기록서 사용 시점** — 설명 가능한 차이, 특이사항, 비교조건 불일치, 재검토 필요
또는 미해결 불일치가 나온 항목에 사용한다. 단순히 일치한 항목마다 만들 필요는 없다.

**10. 종합판정** — 비교조건이 일치하고 미해결 불일치가 없으며 필요한 수정·재산출·재검토가
끝났을 때만 승인 검토 가능으로 표시한다.

**11. 작성 완료 전 점검**

```

```
