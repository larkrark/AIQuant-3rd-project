**내 트랙의 결함이다.** 상대 산출물이 아니라 내 코드에서 나왔다.

`06_코드/qa/paths.py`가 `SEED_BASKET`을 `input_data/seed_basket.csv`로 두고
주석에 `유니버스 정본`이라고 적어 두었다. 그런데 그 파일은 **미국 9종목뿐이다.**

`INPUT_MANIFEST.md` 15행이 이미 명기하고 있었다.

```
`../seed_basket.csv` | 수기 (권보성 — 미국 9종목분) | ... | 김근형 마스터(한국 9종목)와 병합 후 고정
```

병합 정본은 `data/pilot_run/input_krxbm/seed_basket.csv`(KR9+US9 = 18행)다.
**문서가 옳고 내 상수 주석이 틀렸다.**

**실제 영향 — 두 개를 구분해야 한다.**

| 대상 | 입력 | 결과 |
|---|---|---|
| `independent/recompute.py` (4~6단계 독립 재산출) | `--input` 기본값 `P.PILOT_INPUT` | **영향 없음.** 산출물 실측 KR 9 · US 9 = 18종목. **10/10 대조는 그대로 유효하다** |
| `data_loader.py` (독립 수집) | `DEFAULT_BASKET = P.SEED_BASKET` | **영향 있음.** KR 행이 유입되지 않아 한국분 수집이 실행되지 않는다 |

**주목할 점: 죽은 코드가 아니라 호출되지 않는 코드였다.**
`data_loader.py`에는 KR 수집경로(`_kr_prices`, pykrx, 137~152행)와
`r.market == "KR"` 분기(219행)가 **이미 구현돼 있다.** 바스켓에 KR 행이 없어서
한 번도 호출되지 않았을 뿐이다. 배선 결함이다.

**따라서 확인된 사실.** 한국 9종목 원자료는 **독립 수집된 적이 없다.**
`INPUT_MANIFEST.md` 16~17행이 뒷받침한다 — `prices_kr.csv`·`listings.csv`·`halts.csv`
전부 `도착 대기 (김근형)`. 즉 **KR9 입력은 단일 출처이며 교차검증되지 않았다.**

이것은 내 담당 범위의 미이행이다. 상대 산출물의 문제가 아니다.

**조치(완료).**

```
paths.py       SEED_BASKET_US / UNIVERSE 로 분리, 오인 사유를 주석에 남김
data_loader.py DEFAULT_BASKET = P.UNIVERSE 로 교체 + docstring 정정
```

**남은 확인사항.** 상수만 고쳤다. **KR9 독립 수집을 실제로 실행하지는 않았다.**
pykrx 경로 동작 확인이 필요하며, 완료 전까지 KR9는 `단일출처·교차검증 미실시`로 기록한다.

**영향범위.** ☑ 문서 · ☑ 입력매핑 — 산출값 변경 없음(재산출은 병합 정본을 이미 사용).

## 부속 3. 종합검토 결과확인서

| 영역 | 검토 | 일치 | 특이사항 | 미해결 |
|---|---:|---:|---:|---:|
| 원자료·식별자 | 9 | **9** | 1 (F-2) | 0 |
| PIT·날짜 | 1 | 1 | 0 | 0 |
| 문서·결정로그 | 2 | 0 | 0 | **2** (F-3·F-4) |

**확인된 일치사항.** KR9 `corp_code` 9/9 완전일치. 서로 다른 두 배포경로에서 나온 값이
앞자리 0까지 동일하다. 유니버스 집합도 병합 정본과 9/9 동일하다.

**확인된 차이.** 회사명 4건 상이 — 3건 음역차이, **1건(079550) 실제 개명**.

**주요 특이사항.** 기업행사 공시가 **가격축·공시축 양쪽에서 부재**하며 사례가 3건이다
(010120 분할, 010120 정정, 079550 개명).

**최초 불일치가 관찰된 위치.** 항목 16 문서·결정로그.
값 계산이 아니라 **수집 재료 범위**에서 처음 갈렸다.

**선행 근본원인 발생단계.** ☑ 확인됨 — **원자료 수집 범위 정의**.
기업행사 공시를 수집 대상으로 지정한 문서가 없다.

**후행 단계 차이와의 관계.** F-3은 가격계열 왜곡(6.6611%p)의 상류 원인이다.
두 사건은 별개가 아니라 같은 원인의 두 증상이다.

**필요한 문서수정.**
① 데이터사전 — 기업행사 원장 스키마·수집 대상 공시유형 · ② 식별자 결합은 종목코드 기준 명문화
③ 조정 경계일 = 상장일(효력발생일 아님) · ④ 비율 산출근거 = 액면가 우선

**필요한 재산출.** 기업행사 원장 확보 후 엔진 정식 재산출. 현재 `corrected_run`은
`QA_REFERENCE_ONLY`이며 **단독 인용 금지**다.

**미결사항.**
- KR9 나머지 8종목의 미반영 기업행사 존재 여부 — **미확인**
- KR9 독립 수집 실행 — **미이행** (상수만 수정)
- 079550 개명 시점·접수번호 — 미확인
- 룰북 §9 재무조건 — 엔진 미구현

**최종판정: ☑ 미결사항 해소 전 승인·성과 단정 불가**

승인 게이트로 넘기지 않는 근거는 F-3이다. 값이 어긋나서가 아니라, **어느 담당의 범위에도
들어 있지 않은 자료가 산출값을 6.6611%p 바꾼다는 것이 실측으로 확인**됐기 때문이다.

**확인문.** 본 검토는 기준 산출물과 독립 검토 산출물이 동일 모집단과 식별자 규칙을
사용하는지 먼저 확인한 뒤 진행했다. 기록된 차이와 특이사항은 확인된 사실과 추정을
구분하여 작성했으며, 확인하지 않은 항목은 `검토범위 밖`으로 적고 `일치`로 표시하지 않았다.
독립성 등급은 9건 중 1건만 `PRIOR_INDEPENDENT`이다. **미해결 불일치 2건이 남아 있어
공식 승인·성과 대결 대상으로 넘기지 않는다.**

## 양식 v0.3 자체에 대한 개선 제안 (4건)

실제로 채워 보며 걸린 것만 적는다.

### ① 독립성 등급 칸이 없다 — 가장 중요하다

비교조건 사전확인표 12행에 **"검토자가 상대 결과를 먼저 보았는가"**가 없다.
본 검토가 실증한다. 같은 `일치` 9건 중 1건은 상대보다 2시간 55분 먼저 확정한
블라인드고, 8건은 상대 값을 본 뒤 조회한 것이다. **칸이 없으면 9건이 모두
같은 무게로 기록된다.**

```
추가 제안 — 비교조건 사전확인표에 1행
독립성 등급: PRIOR_INDEPENDENT / POST_DISCLOSURE_MECHANICAL / SPEC_ASSISTED / DOC_ONLY
근거: 확정 시각 또는 커밋 SHA (검증 가능한 형태)
```

### ② 부속 4 판정 어휘에 `검토범위 밖`이 없다

부속 5-6은 "`해당 없음`, `검토범위 밖`, `NA`로 기록하라"고 지시하는데,
부속 4 어휘표에는 그 값이 **없다.** 지시와 어휘가 어긋난다.
본 검토는 16항목 중 9항목이 범위 밖이었고, 어휘표에 없는 값을 써야 했다.

```
부속 4에 추가
- 검토범위 밖(NOT_REVIEWED): 확인하지 않았음. 일치도 불일치도 아니다.
- 미구현(NOT_IMPLEMENTED): 양쪽 모두 산출이 존재하지 않는다.
```

### ③ 16항목 고정순서가 부분범위 검토를 강제로 왜곡한다

부속 1-3)은 `원자료 → … → 성과`를 전부 훑는 것을 전제한다. 식별자만 보는 검토는
16칸 중 9칸에 `검토범위 밖`을 쓰게 되고, **표만 보면 검토가 부실해 보인다.**
실제로는 범위가 좁고 그 안에서 완결됐다.

```
부속 1-3) 앞에 1행
검토범위 선언: 항목 01·02·03·16  (그 외는 본 검토 대상 아님)
```

### ④ 값이 맞는데 표기가 다른 경우의 판정축이 없다

`079550`은 `corp_code` 일치·종목코드 일치·상태 정상인데 **이름이 다르다.**
현재 어휘로는 `특이사항`밖에 없어 개명과 단순 음역차이가 같은 칸에 들어간다.
본 검토는 4건이 그랬고, 성질이 둘로 갈렸다.

```
부속 1-5) 판정 결과에 축 추가
표기 동일성: 동일 / 음역차이 / 개명·변경확인 / 확인필요
```

### 짚어둘 것 — 양식이 이미 잘 처리한 부분

부속 1-4) 비고의 **"식별자는 문자열로 관리하고 앞자리 0 등 원문 표현을 별도 보존"**은
이번 검토에서 그대로 필요했다. `corp_code 00105855`를 수치로 저장하면 대조가 깨진다.
상대차이율 기준값 0 → NA 규칙도 식별자 대조에서 계산 자체를 배제하는 근거가 됐다.
**이 두 줄은 유지해야 한다.**
