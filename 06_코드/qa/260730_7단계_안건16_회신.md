### 추가 1건 · `B-5` 기업행사 산식

`B-5`가 승인되려면 최소 두 항목의 산식이 필요합니다. **둘 다 룰북·데이터사전에 규정이 없습니다.**

```
① 조정 경계일 = 효력발생일 vs 상장일
   공시가 두 날짜를 다르게 적습니다 — 신주 효력발생일 04-10 / 신주권상장예정일 04-13.
   경계를 04-10 으로 두면 거래정지 구간(04-08~04-10)의 종가 캐리값 788,000 이
   조정되지 않아, 유령하락이 04-13 에서 04-10 으로 위치만 옮겨갑니다.
   가격계열에서는 상장일(=거래재개일)이 경계라고 봅니다.

② 분할비율 산출 근거 축 = 액면가 우선
   발행주식총수 기준: 1,000,000,000 ÷ 300,000,000 = 3.33:1  ← 원공시에서 틀립니다
   액면가 기준     : 5,000원 → 1,000원          = 5:1     ← 원공시에서도 맞습니다
   액면가는 정정항목이 아니므로 정정 반영 여부와 무관하게 옳습니다.
```

정정공시가 이 축을 갈랐습니다. 정정사유가 "발행주식총수 기재정정"이었고,
회사 설명은 *"수권자본주식수로 기재하였기에 유통주식수 기준으로 기재정정"*입니다.

### 추가 1건 · BM 미국분 환율 환산 명문화

합성 BM의 미국 구성분은 **평가일 당일 환율로 원화 환산**됩니다.
환산 없이 지수레벨 비율만 쓰면 공표 BM과 `2.4e-02` 어긋납니다(재현으로 확인).

커스텀 지수가 원화·무헤지이므로 BM도 같은 통화 기준이어야 비교가 성립하며,
**처리 자체는 옳습니다. 다만 어느 규칙 문서에도 명시돼 있지 않습니다.**

`B-2`(환율 적용 시점)와 같은 축이므로 한 안건에 묶어 주시면 좋겠습니다.

## A/B안 작성에 쓰실 수 있는 QA 실측

안건 자료를 직접 작성하신다고 하셨으니, 제가 가진 실측을 드립니다.
`run_meta.json`의 명세만으로 공표 산출물을 재현해 본 결과입니다.

### 엔진이 현재 선택하고 있는 방식

| 미결 항목 | `run_meta.json` 기록값 | 뜻 |
|---|---|---|
| `B-1` 연결 방식 | `SEGMENT_RELINK` | **연결계수 체인** — 제수 조정이 아닙니다 |
| `B-2` 환율 적용 | `SAME_DAY_ECOS` | 평가일 **당일** 환율 |
| `B-3` 휴장 처리 | `COMMON_OPEN_ONLY` | 한·미 **공통 개장일**만 산출 |

이 세 가지로 재현했을 때 지수 59일 최대 상대오차 `1.056e-15`, 합성 BM `2.184e-16`입니다.
부동소수점 한계 수준이므로 **엔진이 실제로 이 방식으로 돌고 있는 것이 확인됩니다.**

> **주의해서 써 주시기 바랍니다.** 이것은 **"엔진이 무엇을 선택했는가"라는 사실**이고,
> **"그러므로 그것을 채택해야 한다"는 근거가 아닙니다.**
> 의결 자리에서 "코드가 이미 이렇게 돼 있으니"로 흐르면 **규칙을 코드가 정한 셈**이 됩니다.
> 7/27 `MIGYEOL.md` F-3에서 같은 우려를 적었습니다.
> A/B안의 **선택지 목록과 영향범위 산정**에는 쓰시고, 채택 근거로는 쓰지 않으시길 부탁드립니다.

### 영향범위 산정에 쓰실 수 있는 사실

```
B-3 의 '환율 결측일 처리' 분기는 파일럿 구간에서 한 번도 발동되지 않았습니다.
  공통 개장일 59일 중 환율 결측 0일.

따라서 결측 처리를 어느 안으로 정하더라도 파일럿 재현값은 바뀌지 않습니다.
'휴장 불일치'(COMMON_OPEN_ONLY) 부분은 실측으로 확인됐고,
'결측일 처리' 부분은 검증된 바가 없습니다 — 두 개를 나눠서 적으시면
영향범위를 더 정확하게 쓸 수 있습니다.
```

`B-1`은 반대입니다. 파일럿 구간에 정기변경 **적용일이 없어** 연결계수와 제수 조정의
차이가 이번 산출에서는 드러나지 않습니다. 다만 **적용일 규칙 자체가 미결**(룰북 245행)이고
산출물에 `effective_date` 열이 없어, 다음 회차부터 즉시 갈립니다.

```

                   그러나 성과는 PERFORMANCE_NOT_FROZEN 을 벗지 못합니다.

   3건 + B-5 기업행사 산식 + BM 미국분 환율 환산 명문화
```

## 수식부록 지적에 대해

맞습니다. 그리고 하나 덧붙이면 — **기업행사가 빠지면 수식부록이 또 반쪽이 됩니다.**

룰북 §13이 데이터사전에 위임한 항목은 네 개입니다.

```
기준지수값 · 휴장 · 기업행사 · 수시변경
```

3건만 닫으면 **기준지수값과 휴장은 채워지지만 기업행사·수시변경이 남습니다.**
`B-5`를 같이 넣으면 위임 항목 네 개 중 세 개가 닫힙니다.

## 덧붙임 · 규칙 이전의 문제 하나

`B-5`는 산식을 정하는 것만으로 닫히지 않을 수 있습니다.
**저장소에 기업행사 원장이 없습니다.**

010120 분할 정보는 **선정 시점보다 47일 앞서 공시돼 있었습니다**
(이사회결의일 02-05 vs 3/31 회차 자료마감일 03-24).

```
아닌 것                          맞는 것
미래 정보를 못 써서 생긴 문제   →  이용 가능했던 공시를 입력에 반영하지 않은 문제
데이터 공급자 한계             →  기업행사 원장이 파이프라인에 없음
look-ahead 위험                →  look-ahead 없이 보정 가능
```

즉 R4(PIT) 위반이 아니라 `INPUT_ERROR_FIX`입니다.
그리고 07-30 교차검토에서 공시 축에서도 같은 결손을 확인했습니다 —
KR9 공시 수집 재료가 정기보고서 전용이고 **주요사항보고서가 0건**입니다.

> 어느 담당의 결함도 아닙니다. 인계본은 선언한 범위 안에서 정확하게 작동합니다.
> **어느 담당의 범위에도 기업행사 공시가 들어 있지 않은 것**이 문제입니다.

조회 도구는 이미 있습니다 — `qa/corrected_run/fetch_dart.py`가 OpenDART `list.json`으로
주요사항보고서를 조회할 수 있습니다. **KR9 전 종목 확대 실행은 아직 하지 않았습니다.**
나머지 8종목에 미반영 기업행사가 더 있는지도 **확인하지 않았습니다** — 단정하지 않겠습니다.

안건 16에 "수집 경로 신설"을 산식과 함께 넣을지는 판단에 맡기겠습니다.
분리하시는 것이 낫다면 별도 안건으로 상정해 주셔도 됩니다.
