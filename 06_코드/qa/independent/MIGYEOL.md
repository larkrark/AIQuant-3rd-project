# 독립 재산출 — 진행 결과와 미결로 막힌 항목

작성: 김민호(QA) · 2026-07-27 · 대상 `rule_version=v0.9-pilot`
근거 문서: [룰북 v0.4](/01_운영문서/260724_커스텀인덱스_구성및산출_룰북_v0.4_결정반영본.md) · [데이터사전](/01_운영문서/데이터사전.md) · [결정로그](/01_운영문서/결정로그.md)

> **한 줄:** 4~6단계(상태코드·ADTV90·구성·가중) 독립 재산출을 완료했고 engine과 **10개 항목 전부 일치**했습니다.
> 7단계(지수 산출)는 **PR 산식이 미결(안건 I·J)이라 규칙 문서만으로는 구현할 수 없어** 멈췄습니다.

---

## 1. 무엇을 했나

역할배정의 "독립 재산출 = 코드 비공유·규칙 문서만으로 별도 구현"에 따라,
engine의 `market_state.py`·`indicators.py`·`composition.py`를 **열지 않고** 룰북 §8.1·§9·§10과
데이터사전·결정로그 조항만 인용해 4~6단계를 다시 구현했습니다. 코드는 `06_코드/qa/independent/`.

| 파일 | 역할 |
|---|---|
| `rules.py` | 규칙 상수 — 각 줄에 근거 조항 병기, `engine/config.py`를 import하지 않음 |
| `recompute.py` | 4단계 상태코드 → 5단계 ADTV90·시즈닝·P10 → 6단계 구성·가중 |
| `crosscheck.py` | engine 산출물과 **단계별** 대조 (지수값 하나가 아니라 단계마다) |

```bash
cd 06_코드/qa/independent
python recompute.py      # 독립 재산출 → out/
python crosscheck.py     # engine 산출물과 대조 → out/crosscheck.csv
```

## 3. 7단계를 못 짠 이유 — 규칙이 아직 없습니다

구현 능력 문제가 아니라 **인용할 조항이 없어서**입니다. 근거는 세 곳입니다.

**① 룰북 §13이 스스로 위임했습니다.**

> 현재 범위: 아래는 산출 모듈을 **연결하기 위한 구조**이며, 기준지수값·휴장·기업행사·수시변경의
> **세부식은 산출규칙 J(데이터사전)에서 확정한다.**

**② 위임받은 데이터사전 §15.2는 필드 목록입니다.** `index_level` 설명이 "기준값 1000에서 연속 산출" — 산식이 아닙니다.

**③ 룰북 §17이 미결로 명시했습니다.**

> **[안건 I·J]** 과거 2개 분기 달력 적용시험, ECOS 환율 세부(통계표·계열코드·단위·방향·기준시각·휴장·결측일·적용일),
> **PR 산식·기준일·기업행사·수시변경 규칙**

지금 구현하려면 아래 빈칸을 제가 임의로 메워야 하는데, 그건 **룰북 R2 위반**(미결 항목을 확정처럼 쓰지 않는다)입니다.
게다가 임의로 메우면 engine과 값이 달라도 그게 engine 문제인지 제 선택 차이인지 구분할 수 없어 **검증으로서 무의미**해집니다.

### 결정이 필요한 항목 (B = 7단계 블로킹)

| ID | 항목 | 현재 문서 상태 | 필요한 결정 |
|---|---|---|---|
| **B-1** | 정기변경 연결 방식 | 룰북 §13.5 "연결계수 **또는** 제수 조정" | 둘 중 하나 확정 + 산식. 결과가 달라집니다 |
| **B-2** | 환율 적용 시점 | 룰북 §12.3 **[미결]** | 선정일·효력발생일 각각 어느 날 환율을 쓰는지 |
| **B-3** | 휴장 불일치·환율 결측일 | 룰북 §12.3 **[미결]** | 한국 공휴일에 미국 개장 시 처리(직전값 이월 / 해당일 제외 / 기타) |
| **B-4** | ECOS 계열 세부 | 룰북 §12.3 **[미결]**, 사전 §15.3 `fx_series_code` "데이터 사전에 고정" | 통계표·계열코드·단위·방향·기준시각 확정 (현재 코드에 731Y001 잠정값 사용 중) |
| **B-5** | 기업행사·수시변경 | 룰북 §17 안건 I·J | 분할·합병 발생 시 지수 연속성 처리 |

B-1~B-3만 확정되면 7단계를 바로 짤 수 있습니다. B-4·B-5는 파일럿 구간에 해당 사건이 없어 후순위여도 됩니다.

## 4. 제가 가정으로 메운 항목 (4~6단계, 비블로킹)

4~6단계도 문서에 없는 칸이 몇 개 있었습니다. **임의로 정하고 여기 공개**합니다 — 팀 확인 부탁드립니다.
셋 다 이번 데이터에서는 결과를 바꾸지 않았지만, 데이터가 바뀌면 바꿀 수 있습니다.

| ID | 항목 | 문서 상태 | 제 가정 | 영향 |
|---|---|---|---|---|
| **U-1** | 상태코드 판정 우선순위 | 룰북 §8.1은 `TRADING_HALT > ZERO_VOLUME`만 명시 | 휴장 → 상장여부 → 정지 → 결측 → 무거래 → 정상 | 없음(engine과 일치) |
| **U-2** | 백분위 산출 방법 | 룰북 §8.1은 "P5·P10·P25·P50·P75로 산출"만 규정 | 선형보간 | 없음(engine과 일치) |
| **U-3** | ADTV90 관측 종료일 | 아래 F-1 참조 | 자료마감일 | **있음** — F-1 |

## 5. 발견사항 (F)

### F-1 · ADTV90 관측 종료일이 자료마감일이 아니라 선정일입니다

engine 산출물 `adtv90_ledger.csv`의 `observation_end_date`가 **선정일과 같습니다**(2026-06-30).
그런데 문서 두 곳은 자료마감일 기준을 말합니다.

- 결정로그 **D-13 ⑧**: 자료마감일(`data_cutoff_date`) = 선정일 이전 제5거래일, 한·미 공통 개장일 축 역산
- 룰북 **R4/§5.2 (PIT)**: 자료마감일 **이전에 이용 가능했던 자료만** 사용, look-ahead 금지

선정일 종가까지 관측창에 넣으면 자료마감일 이후 5거래일치 정보를 쓰는 셈이라 PIT 원칙과 어긋납니다.

**영향 확인 (제가 양쪽 다 돌려봤습니다):**

| 관측 종료일 | 2026-06-30 회차 P10 (KR) | 편입 결과 |
|---|---|---|
| 선정일 06-30 (engine 현재) | 1,268.8억 | 15/18 |
| 자료마감일 06-23 (PIT 정합) | 1,276.3억 | **15/18 — 동일** |

**편입 종목은 바뀌지 않았습니다.** ADTV90이 움직이면 P10 하한도 같이 움직여 상쇄되기 때문입니다.
즉 **지금 당장 산출물을 고칠 사안은 아니지만**, 정식 산출 전에는 정리해야 합니다.
데이터가 바뀌거나 유니버스가 커지면 상쇄가 보장되지 않습니다.

요청: 어느 쪽이 규칙인지 확정해 주십시오. ① D-13 ⑧대로 자료마감일로 통일 / ② 선정일이 맞다면 D-13 ⑧ 문안 수정.
**규칙 조정이 아니라 기존 결정의 코드 반영 확인**이므로 R3(성과 기반 조정 금지)에 저촉되지 않는다고 봅니다.

### F-2 · `valuation_price_source`가 산출물에 남지 않습니다

`engine/index_calc.py`는 `adj_close` 부재 시 `raw_close` 폴백을 쓰면서 `valuation_price_source`를 세팅하고
**콘솔 경고만** 남깁니다. 어떤 산출 파일에도 기록되지 않아, 산출물만 받은 사람은 폴백 사실을 알 수 없습니다.
이번 파일럿이 실제로 이 상태입니다(`prices.csv`에 `adj_close` 열 없음).

요청: 기록 위치 지정(`daily_market_state.csv` 열 추가 또는 산출 메타 JSON).

### F-3 · 미결 항목이 코드에서는 이미 특정 방식으로 구현돼 있습니다

B-1(연결계수/제수)·B-3(환율 결측)은 문서상 미결이지만 engine은 이미 어느 한쪽으로 돌고 있습니다.
안건 I·J 의결 때 "코드가 이미 이렇게 돼 있으니"로 흐르면 규칙을 코드가 정한 셈이 됩니다.

요청: 의결 **전에** engine이 실제로 선택한 방식을 명세로 뽑아 안건 자료에 첨부. (엔진 담당분이라 제가 손대지 않았습니다.)

## 6. 요청 정리

| 우선 | 대상 | 내용 |
|---|---|---|
| 1 | 전원 | **B-1·B-2·B-3 확정** — 이것만 되면 7단계 독립 재산출 착수 가능 |
| 2 | 전원 | **F-1 확정** — 관측 종료일 = 자료마감일인지 선정일인지 |
| 3 | 엔진 담당 | **F-2** 폴백 사실 기록 위치 지정 |
| 4 | 엔진 담당 | **F-3** 안건 I·J 의결 전 현행 구현 방식 명세화 |
| 5 | 전원 | **U-1·U-2** 가정 승인 또는 대체 규칙 지정 |
| 6 | 안건 F | **KTOS 사례**(하한 대비 -0.5%)를 버퍼 폭 논의에 포함 |

7단계를 뺀 나머지는 독립 재산출이 끝났고 engine과 전 항목 일치합니다.
**4~6단계 산출 로직은 두 사람이 각각 구현해 같은 답을 낸 상태**로 보셔도 됩니다.
